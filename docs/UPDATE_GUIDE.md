# アプリ更新の運用

利用者はサイトを開かず、アプリ内で更新できます。配布サイトは更新を置く側の管理画面と、アプリが裏でアクセスする配信元です。

- 配布・変更履歴: https://digitalbuilder-gr-updates.rinntyu2000.chatgpt.site
- 管理画面: https://digitalbuilder-gr-updates.rinntyu2000.chatgpt.site/admin
- アプリ用の更新情報: https://digitalbuilder-gr-updates.rinntyu2000.chatgpt.site/api/releases/latest

## 利用者の操作

### 初めて使うWindows 11のPC

サイトの「セットアップEXE」を開き、保存先を確認して導入します。小さなEXEが初回だけPythonと必要な部品を取得・検証し、初期化が成功した後に一時ZIPを削除します。標準保存先はユーザーのLocalAppData配下のPrograms/Digitalbuilder GRです。スタートメニューと、選択した場合はデスクトップにショートカットを作成します。以降はショートカットまたはDigitalbuilder GR.exeで起動できます。

Python・pip・Playwrightの事前インストールは不要です。請求取得ではWindowsのEdgeを画面を出さずに再利用し、EdgeがないPCに限り専用ブラウザーを初回取得します。Edgeの起動が組織のポリシー等で拒否された場合は停止して案内し、別ブラウザーに黙って切り替えません。以前の配布版で同梱ブラウザーがある環境は、引き続きそれを使います。初回起動後にDigital Billderのログイン設定を行います。台帳はアプリフォルダーのdataへ、パスワードはそのWindowsユーザーの資格情報ストアへ保存します。

Python本体や必要な部品はアプリの実行に必要なので、自動削除しません。自動削除の対象はセットアップが作成した専用の一時ファイルだけです。ダウンロードした小さなセットアップEXEは導入後に手動で削除できます。既存のアプリフォルダーへ上書きインストールはせず、既存利用者はアプリ内更新を使用します。

ZIPを直接取得した場合は、ZIP内から直接実行せず、すべて新しいフォルダーへ解凍してDigitalbuilder GR.exeまたは起動.batを開いてください。社内PCのアプリ実行制限は管理者の設定に従います。Windows 11 x64の実行環境を対象とし、ARM端末や全社内ポリシーでの動作を検証済みとはしません。

### 既に使用中のアプリを更新する

1. 更新前から開いていたアプリを通常の操作で閉じ、`起動.bat`から起動し直します。これで今回追加した更新ボタンと固定の起動入口が使われます。
2. 管理画面の設定グループで「アプリの更新」を開きます。
3. 「更新を確認」で現在版・最新版・変更内容を確認し、ダウンロードします。
4. 編集・取込・履歴取得などの作業画面を閉じてから、更新して再起動します。開いた作業や未保存メモがある場合は適用を保留します。

配布サイトをブラウザーで開く必要はありません。サイトの「手動更新ZIP（起動.bat入り）」から手動でも更新できます。既存環境向けの配布で、Pythonや依存ライブラリ込みの新規インストーラーではありません。手動取得したZIPを台帳フォルダへ上書きしないでください。

### ZIPから手動で更新・起動する

1. サイトの「手動更新ZIP（起動.bat入り）」をダウンロードし、新しいフォルダーへすべて解凍します。
2. アプリを通常の操作で閉じ、解凍した「起動.bat」を開きます。
3. 今まで使っていたアプリのフォルダー（元の起動.batがある場所）を選び、表示された台帳の保存先を確認します。
4. 元のアプリの専用Python環境で署名とファイルを検証し、バックアップ・更新・起動を行います。同じ版か新しい版を使用済みなら、その版を起動します。

以降は元のアプリの起動.batから起動できます。ZIP内のupdate.zipを個別に解凍したり、app.pyを標準Pythonで直接実行したりする必要はありません。更新機構と.venvがある既存アプリ、WindowsのPythonランチャー（py）、既存台帳が必要です。

手動用ZIPは、公開中の署名済み更新ZIPと対応manifestに起動.bat・manual_update.py・説明を添えたものです。アプリ内更新用ZIPは従来のままで、配布済みの更新機能でも取得できます。起動セットの内容を変更するときはmanual-r番号を上げます。配布を停止した版は手動用ZIPも取得できません。

## 保護されるもの

台帳、請求PDF、予算原本、除外状態、履歴、Web操作の凍結状態は従来のdataに保持します。パスワードはWindows資格情報ストアのままです。更新前にSQLiteの一貫したバックアップを取り、署名を確認したコードを別フォルダへ準備してから切り替えます。

固定の`launcher.py`が`.updates/current.json`で選ぶ版を起動します。初回は従来のアプリを使い、更新後は`.updates/releases/`内の検証済みの版を使います。元の開発用コードは上書きしません。更新失敗や途中の電源断はジャーナルから復旧し、起動を確認していない版をそのまま有効扱いしません。

初版は同じPython・依存関係・DB形式での更新だけを受け付けます。環境の識別情報が異なる場合は、更新を止めて現在版を維持します。DB移行やPython環境の自動更新、更新機構自体の入替えは別の導入手順が必要です。

## 更新を用意する側の標準手順

1. 対象の修正を行い、必要なテストを実行します。稼働中の台帳へ試験データを入れません。
2. サイトの配布履歴を確認し、未使用の版番号と、それまでより大きい配布番号を決めます。
3. 対象ソース・変更履歴・検証結果を確認して通常アプリへコミット・プッシュし、その確定したソースから仮想環境で配布ファイルを作ります。例の番号は次回そのまま使わず、履歴と照合してください。

```powershell
.\.venv\Scripts\python.exe tools\build_release.py --version 1.0.4 --sequence 4 --output-dir 'C:\Users\rinnt\Documents\Codex\Digitalbuilder＿GR\作業補助\配布ファイル' --notes "今回の具体的な変更内容"
```

4. ZIP、署名付きmanifest JSON、公開鍵JSONが出ます。秘密鍵はWindows資格情報ストアに保存され、ファイルへ出ません。台帳・実PDF・.git・設定・秘密鍵がZIPに入っていないことを検査します。
5. 管理画面へ所有者のChatGPTアカウントでログインし、ZIPと署名付きmanifest JSONをアップロード。「検証して登録」の後に内容を確認して「配布を開始」を押します。
6. 公開された更新情報とZIPを取得して、署名・サイズ・ハッシュを確認します。隔離した台帳でアプリ側の準備・適用・起動確認も実施します。
7. 新規PC向けのWindows同梱版とサイトのダウンロード案内も更新し、変更履歴と検証結果を残します。2026-09-05の継続許可に基づき、今後は検証済みの作業の区切りでコミット・プッシュし、新バージョンが確定した作業ではサイトへの公開・取得確認まで完了します。詳細は [開発・配布の指示](../AGENTS.md) に従います。これはエージェントの作業ルールであり、時刻指定の定期実行は設定しません。

### 新規PC向け同梱版も更新する

2026-09-06以降は `build_windows_distribution.py --vc-runtime-dir <検証済みx64再配布DLLフォルダー>` が必須。公式のVisual C++再配布元から `msvcp140.dll`、`vcruntime140.dll`、`vcruntime140_1.dll` を同じ版で準備する。ビルダーはMicrosoft署名、x64、版一致、SHA256、リンク不在を確認し、アプリ専用runtimeに配置する。System32や他アプリからDLLを拾う運用はしない。`runtime/vc-runtime.json` に版・ファイル名・ハッシュを記録し、署名ZIPの対象に含める。

確認済みの供給元は [Microsoft公式VC再配布パッケージ](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170) のx64版14.51.36247.0。ローカル取得EXEのSHA256は `843068991daaa1f73ad9f6239bce4d0f6a07a51f18c37ea2a867e9beca71295c`。展開元は `作業補助/WindowsTest/pdf-runtime-source/` に保管し、一般配布・Gitへ開発用原本を含めない。将来の取得では公式署名と版を改めて照合する。

アプリ専用DLLはWindows Updateによる共有ランタイム更新とは別に管理されるため、配布環境を更新する際に公式ランタイムの更新も確認する。セットアップの再実行は既存の空でない保存先を拒否する。新規同梱版を台帳やruntimeへ手動で上書きしない。今回のDLL追加は通常のコード更新では既存導入先へ届かず、既存環境の移行はバックアップを含む別の手順として扱う。

署名済みコードZIPとmanifestを `tools/build_windows_distribution.py` の `--release-zip` と `--release-manifest` に指定します。`--distribution-sequence` はWindows版専用の未使用連番、`--build` は同じアプリ版の同梱セット番号です。2026-09-05時点の公開版はアプリ1.0.3・コード番号3、Windows配布番号2・build2です。これらの番号と出力フォルダーを使い回しません。

生成したWindows ZIPと専用manifestを管理画面のWindows版欄から登録・公開し、サイトから実際に取得したZIPを別フォルダーへ解凍します。同梱runtimeのみで起動.bat・ログイン保存・実データ取得・再起動後の表示を確認してください。実測記録は [配布版の実機検証](DISTRIBUTION_VERIFICATION.md) を参照します。

軽量版は `build_windows_distribution.py --browser-mode edge-or-download` で作成します。完成した署名付きWindows版から `build_windows_setup.py --archive <ZIP> --manifest <署名JSON> --output-dir <新規出力先>` でセットアップを生成します。Setup.csをコンパイルする前に署名と全体SHA-256を確認し、EXEへ配布元URL・サイズ・ハッシュ・期限を固定します。生成したEXEとメタデータをサイトの配布物に反映し、公開サイトから取得したセットアップで初期化・一時ファイル削除・ショートカットを確認します。

機械登録用の期限付きトークンを使った場合は、終了時にハッシュを無効値へ置換し、有効期限を過去日にしてサイトへ反映します。実際にそのトークンを使った管理API要求が403になることを確認します。環境項目を削除したという結果だけで無効化完了とは判断しません。

署名期限の標準値は30日、作成時の最大値は90日です。期限切れの新規適用は拒否しますが、既に正常起動を確認して有効になった版は署名情報が期限切れになっても起動できます。今後の修正は新しい版として配布し、公開済みファイルを差し替えません。

## 配布停止

管理画面の「配布を停止」は、その版の新規ダウンロードを停止します。利用者のPCへ適用済みの版を強制的に戻す機能ではありません。最新の版を停止した場合も、古い配布版を勝手に最新版へ繰り上げません。修正版を新しい配布番号で公開してください。

管理者は最初の認証済み所有者アカウントのSite内IDで固定します。一般利用者は配布ファイルと変更履歴だけ取得できます。サイト初回登録に使う機械操作用のトークンは利用者用アプリに含めず、登録後に無効化します。
