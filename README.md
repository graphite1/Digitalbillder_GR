# Digital Billder請求書 補助台帳アプリ

Windowsローカルで動作する、Digital Billder請求書向けの補助台帳アプリです。
Digital Billderを置き換えず、CSVとzip内PDF原本をローカルで保存・検索・集計します。

詳細な機能仕様、画面仕様、制限値は [SPECIFICATIONS.md](SPECIFICATIONS.md) を参照してください。

## アプリ方針

- Digital Billder側の登録状態、承認状態、支払状態は管理しません。
- 現行の請求書振分は手動入力・履歴候補を基本とします。将来はMCP接続とPDF内部情報・OCRによるAI振分を追加し、利用者の最終確認へ引き継ぎます（上記方針参照・未実装）。
- 新着取込ではDigital Billderにログインし、CSV・ZIPをダウンロードします。
- CSVに含まれる請求情報と、zip内PDF原本をローカルで安全に扱います。
- CSVの税込原本額を保持したまま、画面内の金額計算と振分入力は税抜を基本にします。
- 請求一覧、詳細確認、添付PDF参照、メモ、請求月管理、Excel出力を補助します。
- GUI起動時は請求一覧画面を最初に表示し、管理メニューから取込やマスタ画面を開きます。
- 請求詳細のPDFプレビュー上で、工種コード振分に対応する確認用マークを配置できます。
- 請求詳細画面から、マークを重ねた確認用PDFを別ファイルとして出力できます。
- PDFマーク座標はPDFページ上の実座標を基準に扱い、既存の比率座標データは互換表示します。

## Digital Billderから新着取込

管理メニューの「Digital Billder 新着取込」で、ブラウザ画面を開かずに未確認の請求を取得できます。
初回は「ログイン設定」を保存し、「新着確認」で取得した一覧から必要な請求を選んで取り込みます。
誤請求などは「選択を除外」で記録し、次回から候補に表示しません。除外は解除できます。

初回セットアップ（仮想環境内で実行）:

```powershell
python -m pip install -r requirements.txt
python -m playwright install chromium --only-shell
```

パスワードはWindowsの資格情報マネージャーに保存します。
詳細は [新着取込の操作・制限](docs/DIGITAL_BILLDER_SYNC.md) を参照してください。

## 請求月ルール

請求月は請求日から自動判定します。

- 毎月10日から翌月9日までを同じ請求月とします。
- 例: 2026-04-10 から 2026-05-09 までの請求日は 2026年5月請求です。
- 例: 2026-05-10 から 2026-06-09 までの請求日は 2026年6月請求です。
- CSV取込時は、各行の請求日ごとに請求月を判定します。
- CSV内に複数の請求月が混在していても、行単位で請求月を保存します。
- CSV取込では請求日を必須とし、空欄の場合は取込エラーとして請求月を自動記入しません。
- 例外対応のため、請求一覧画面の手動請求月変更機能を残します。自動判定と異なる月へ変更した請求は手動補正として保存し、再計算の対象から外します。

## 安全運用

`data/` 配下にはSQLite DB、DBバックアップ、PDF原本、Excel出力が保存されます。
請求情報や取引先情報を含むため、共有フォルダやGit管理対象には置かないでください。

CSV + zip取込では、zipサイズ、PDFサイズ、PDF件数、ファイル名の安全性を確認します。
PDF原本は `data/originals` 配下に保存し、アプリ内のPDF表示・PDFを開く操作もこの配下のPDFだけを対象にします。

Excel出力では、CSV由来の文字列がExcel数式として実行されないように無害化します。

CSV + zip取込、請求月変更、請求月再計算、請求削除の直前には、`data/backups/` へSQLite DBを自動バックアップします。起動時にはバックアップを行わず、メイン画面の表示時間を優先します。

## 画面方針

請求一覧画面は、毎月の確認作業を短時間で進めるための画面です。

- 表示件数と請求金額合計を確認できるようにします。
- 工事、請求月、取引先、請求日、並び順で絞り込みできるようにします。
- 工事選択は終了前の選択を保存し、次回起動時に復元します。対象工事が非表示の場合は `すべて` に戻します。
- 更新が終了した工事はアーカイブにでき、データを削除せず表示へ戻せます。アーカイブ中は取込と変更処理の対象外です。
- 工事表示設定では、工事コード・工事名の検索、請求件数、最終請求日を確認できます。
- 管理メニューの取込履歴では、取込日時、ファイル名、登録・PDF・エラー件数、完了状態を確認できます。
- CSV + zip取込後に管理メニューを閉じると、一覧とフィルタ候補を再読込します。
- 行選択を前提とする操作は、未選択時に実行できないようにします。
- 詳細確認、メモ編集、請求月変更、添付PDF表示を行単位で実行します。
- 画面の大改造より、確認にかかる手数を減らす改善を優先します。

## 追加機能（2026-09-05）

- 管理メニュー → **保管済み履歴・工事別実績**: Webの保管済み査定額を工事・会社・工種で集計します。初回は詳細取得が必要です。「追加・変更分を確認」は一覧を照合して確認済み明細を再利用し、「全件を再検証」は過去の査定変更も読み直します。
- 請求詳細 → **履歴候補**: 会社別の使用頻度・金額を参考に工種を選びます。振分金額の自動確定はしません。未登録工種は選択してこの工事へ追加できます。
- 管理メニュー → **工事予算・着地見込**: PDFの2ページ目をセル構造から読み、コード・科目・実行予算・予定金額を候補にします。登録前・登録後の手動編集に対応し、元PDFと抽出値を保持します。[使い方と読取限界](docs/PROJECT_BUDGET.md)。
- 請求詳細の税率は **10%・8%・非課税**。請求原本との照合は税込合計を使います。請求全体の税抜表示と従来の一部帳票は10%換算です。
- **Web転記プレビュー**で既存査定との差分を確認できます。Web書込みは試験請求の準備待ちで無効です。到達点は「編集を保存」、禁止操作は「アクション → 次に回す」。[実装状況と次の作業](docs/WEB_ALLOCATION_HANDOFF.md)。

通常の履歴確認で、会社・工事・請求日・税込額などが変わらない査定だけの修正は検出できません。その場合は「全件を再検証」を使います。自動の定期巡回は実装していません。

コード更新後は、実行中の取得が終わってからアプリを閉じ、`起動.bat`で起動し直してください。起動時に既存データを維持してDB項目を追加します。

## Windows向け配布と起動

初めて使うPCでは、[配布サイト](https://digitalbuilder-gr-updates.rinntyu2000.chatgpt.site/)のセットアップEXEから導入します。Pythonと必要な部品を初回だけ取得・検証し、完了後はショートカットまたは `Digitalbuilder GR.exe` から起動できます。

- Pythonの事前インストールは不要です。取得した一時ZIPはセットアップ完了後に削除し、実行環境と台帳は保持します。
- 軽量版は既存のEdgeを画面を出さずに再利用します。EdgeがないPCに限り、専用ブラウザーを初回取得します。
- 実データ、ログイン情報、開発用の仮想環境やテストは配布しません。各自のログイン情報は初回に設定します。
- 導入後のコード更新はアプリ内から行います。既存フォルダーへセットアップを上書きせず、台帳を保持する更新機構を利用します。
- 開発環境とZIP直接配布では引き続き `起動.bat` も使用できます。詳細は [更新・初回導入の手順](docs/UPDATE_GUIDE.md) を参照してください。
